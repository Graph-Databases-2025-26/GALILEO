\subsection{Adaptive Strategy Selection}
The framework includes an \textbf{auto} execution mode that dynamically selects between Table-Scan and Key-Scan. This decision is mediated by the \textbf{ConfidenceEstimator}, which evaluates the query complexity and the number of requested columns. The confidence estimation logic incorporates a penalty factor based on the query's complexity. The final confidence score \texttt{$C_{final}$} is not merely the raw probability returned by the model ($C_{raw}$), but is exponentially decayed by the number of selected columns ($N_{cols}$):

\centering
$C_{final} = (C_{raw})^{N_{cols}}$
\centering

If $C_{final}$  is below a specific threshold ($\tau$) or if the schema is particularly wide, the system defaults to the Key-Scan strategy to ensure data integrity, otherwise, it proceeds with the more direct Table-Scan.

More deeply this formulation models the increasing difficulty of retrieving coherent tuples as the schema width grows. Consequently, queries requesting a large number of attributes result in lower confidence scores, biasing the physical optimizer towards the safer Key-Scan strategy rather than a direct Table-Scan.
This handling mode is useful for GALOIS-F logical plan.
